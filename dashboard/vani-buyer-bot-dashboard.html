    How this audit works

    Our approach

    We audit every call handled by Vani_voice_bot, IndiaMART’s buyer-side voice agent, against the 16-parameter VANI Call Quality Matrix — then turn the failures into prompt fixes that ship back to the bot.

    1 What we audit

    The agent under test

    Vani_voice_bot — IndiaMART’s buyer-side voice agent. Every call it handles in the audit window is in scope: inbound and outbound, across products, cities and languages.

    What we look at

    The call log and the full transcript of each call: the buyer’s stated requirement, what the agent captured, how it probed, where it looped or went silent, and how the handover to a seller fired.

    4 How we score

    Passclean — no defect
    Fatalbreaks the call or the lead
    Non-fatala defect that didn’t break the call
    N/Athe parameter did not apply
    Unscorableapplied, but the data was missing
    Overall Call verdict — Fatal if any parameter is Fatal; Non-fatal if any is Non-fatal; otherwise Pass. A call whose verdict could have changed had an Unscorable parameter been known is marked partial.

    5 What comes out

    Step 1AuditEvery call scored against the matrix, each Fatal and Non-fatal tied to a call, a turn and a quote.
    Step 2GroupFailures rolled into root causes, ranked by frequency × severity.
    Step 3FixA minimal prompt diff drafted for each root cause.
    Step 4TestThe fix is run against the bot’s test suite before it ships to the draft.

    6 Cadence

    Audit runs are scheduled weekly. Each week becomes its own tab in the run list, so a run can be compared against the one before it — the same calls, the same matrix, and the fixes that moved the numbers.
